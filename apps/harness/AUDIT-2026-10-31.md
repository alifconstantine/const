# Harness, remote, mobile, router and accounts audit

Date: 2026-10-31 (Asia/Jakarta).

## Evidence and scope

Reviewed desktop chat execution, SSE recovery, session snapshots, remote relay and
pairing, the bundled mobile workspace, browser captures/input, router request
forwarding and metering, and Accounts redirect/authentication boundaries.

Read the user's local Harness SQLite history in read-only mode. The Saltwake run
shown in the report contained nine model requests, roughly 24 minutes of elapsed
work, more than 186,000 characters of reasoning, and no tool calls. Several
requests ended at approximately 180 seconds without usage. This matches the
router's old three-minute deadline; the old agent accepted an unterminated SSE
stream as completed and then repeatedly retried unusable output. The history
does not establish whether the engine also imposes its own timeout.

No credentials or complete private transcripts are included in this report.

## Findings addressed

| Severity | Finding | Result |
| --- | --- | --- |
| High | Accounts trusted arbitrary `*.vercel.app` destinations while appending authentication tokens. HTTP production targets and unrestricted LAN redirects were also accepted. | Production redirects require the official HTTPS ecosystem, registered native schemes, or the explicit loopback callback. Development LAN targets remain development-only. Control characters, backslashes and URL credentials are rejected. |
| High | Desktop deep links accepted mismatched login state; the loopback callback accepted missing state and consumed its nonce before validating the token. | Both paths require an active matching nonce. Malformed callbacks cannot consume the loopback nonce, and replayed callbacks fail. |
| High | Dropped SSE streams could be recorded as successful. Output-limit tool calls could execute with unfinished arguments. | Shared stream consumer requires terminal evidence, handles trailing frames/Unicode, closes readers on failure, and never executes length-truncated calls. |
| Medium | Reasoning-only generations and empty responses could repeatedly replay without progress. Waiting for headers or heartbeat-only streams could be unbounded. | One reasoning recovery, two empty/transport retries, cancellable backoff, 90-second header deadline, and ten-minute generation deadline. Interrupted reasoning recovery retains bounded context and preserves the user's original scope. |
| Medium | Router cut reasoning generations at 180 seconds and silently dropped `parallel_tool_calls: false`. | Default deadline is ten minutes, configurable with `ROUTER_UPSTREAM_TIMEOUT_MS` up to fifteen minutes. Tool serialization preference is validated and forwarded. Unterminated upstream EOF emits an explicit error and settles metering as failure; client cancellation is distinct from upstream timeout. |
| Medium | Working duration restarted after refresh because the renderer owned the start timestamp. | Native and remote hydration recover host start time and run identity. Snapshot replay includes the host timestamp. |
| Medium | Closing the desktop revoked pairing. Starting another desktop revoked offline hosts. A transient heartbeat/publication failure could also revoke a session. | Normal close suspends the transport. OS-encrypted host credentials allow resume after reopening; explicit stop/sign-out still revokes. Offline sessions remain registered, temporary transport failures retain grants, and slow event feeds recover from snapshots. |
| Medium | Remote sessions expired after eight hours even while enabled. | Authenticated host heartbeats renew a 30-day inactivity lifetime. Cleanup reschedules safely, new pairing invitations still expire after 15 minutes, and retained sessions are capped at 20 per account with at most four online hosts. |
| Medium | Mobile lost its active connection/device proof when the WebView was recreated and relied on the expiring invitation code for reconnect. | Account-scoped pairings and an opted-in persistent device grant survive recreation. Existing pairings reconnect without resolving the invitation again. Sign-out/session removal clears stored credentials. |
| Medium | Pulling in the mobile workspace could invoke `location.reload()` during normal use. | The production workspace no longer mounts the page-reloading gesture. Explicit reload remains available. |
| Medium | Remote browser frames requested AI screenshot annotations by default; concurrent AI captures could contaminate clean captures. | Remote frames explicitly disable annotations. Browser screenshots are serialized and clean up masks/annotations between captures. |
| Medium | The remote browser image supported wheel scrolling but not touch swipes. | Touch/pen swipes send scroll input and suppress accidental clicks; cancelled gestures clear state. |
| Low | Mobile account page lacked account identity, theme and language controls. Hardcoded dark surfaces ignored light mode. | Shows verified profile name/email, persistent system/light/dark theme, and English/Indonesian/Japanese/Chinese/Spanish controls. Workspace starts with shell preferences. |
| Low | Mobile sidebar menu target was 36×36 and its light-theme hover ink became white. | Menu target is 44×44, with theme-appropriate ink. |
| Low | Windows CRLF conversion invalidated model catalog byte hashes. | `.gitattributes` preserves LF for hashed catalog JSON. Offline AI and agent builds pass with the committed catalog. |

Removed the duplicate trailing SSE parsing path and unused stream bookkeeping.

## Deployment and remaining verification

This audit covers the paths above, not a guarantee that the whole platform has no
remaining defects. No authenticated live model generation or physical Android
device test was performed. OS process reclamation can still recreate a WebView;
the new pairing restoration is intended to recover that state.

Server changes require deployment of router, Accounts and Convex backend. Desktop
and Android installations must use the rebuilt application. Existing eight-hour
sessions renew on their next authenticated heartbeat after the backend update;
already expired/revoked sessions must be enabled/paired again.

Desktop resume requires an available OS encryption store and valid account
authentication. Linux's plaintext `basic_text` key store is deliberately not
used for persisted host credentials. Sessions remain offline while the desktop
process is closed; no background host was added.

Production bundles still report large-chunk and third-party annotation warnings.
These are build warnings, not evidence of a confirmed mobile process crash.
