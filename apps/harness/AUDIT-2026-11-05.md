## Temuan sebelum implementasi

### P1 — Batas per gambar tidak menjamin total request muat

- `packages/agent/src/const/tools.ts:5846`: pembacaan gambar mengizinkan file sampai 3 MiB dan mengirim byte asli sebagai base64; tidak melakukan resize otomatis.
- `packages/agent/src/const/tool-observations.ts:9`: mempertahankan dua gambar terbaru, dengan batas 4 MiB base64 **per gambar**. Dua gambar yang masing-masing valid dapat melampaui batas body gateway saat digabungkan.
- `packages/agent/src/const/const-agent.ts:1083`: body diserialisasi langsung ke fetch. Tidak ada pemeriksaan `Buffer.byteLength` untuk keseluruhan body, termasuk pesan, tool schema, dan media.
- `model-retry.ts` mengenali context overflow dan capability rejection, tetapi tidak mempunyai recovery khusus payload 413. Penolakan ini diteruskan sebagai error terminal. Menambah retry identik tidak menyelesaikan ukuran body.
- Meter token memperkirakan gambar sebagai 1.600 token per gambar (`token-meter.ts:264`); angka tersebut bukan estimator ukuran transfer HTTP. Tampilan context 2% tidak menjanjikan body request masih muat.

### P2 — Semua akhir session diberi notifikasi sukses

- `apps/harness/desktop/electron/main.ts:1565`: `finishSession` mengirim `agent:session-ended` hanya dengan conversationId dan runId.
- Fungsi tersebut dipanggil dari `finally`, termasuk setelah `agent.run` melempar error.
- `apps/harness/desktop/src/App.tsx:2506`: listener event ini mengirim notifikasi **Task Completed** dan suara completion bila pengaturan terkait aktif, tanpa memeriksa hasil run.
- Frontend memang menampilkan toast error dan menyimpan teks error (`App.tsx:3104`). Jadi bukan seluruh pelaporan error hilang; notifikasi dan suara sukses tetap dapat bertentangan dengan kegagalan sebenarnya.

### P2 — Pemendekan konteks dapat membuang spesifikasi awal

`compactHistoryForContext` (`const-agent.ts:303`) memangkas pesan user lama >800 karakter menjadi potongan awal 300 karakter dan akhir 150 karakter plus penanda. Jika pengguna mengirim “lanjutkan”, brief awal tidak lagi merupakan user message terbaru. `fitRequestHistory` dijalankan setelah pemangkasan tersebut; pinning pesan pertama tidak mengembalikan bagian yang sudah hilang.

Probe offline memakai brief asli chat terbaru dan follow-up sintetis “lanjutkan”: **28.655 karakter menjadi 540 karakter**. Transcript asli tetap utuh, tetapi model hanya melihat versi pendek dalam request. Ini bukan penyebab HTTP 413, tetapi merupakan risiko hilangnya detail pekerjaan pada kelanjutan chat.

### P2 — Tool bernama Bash dapat dijalankan oleh Fish

`getShellConfig` (`tools.ts:157`) memilih `process.env.SHELL` terlebih dahulu lalu memberi `type: "bash"` pada shell Unix yang ditemukan, termasuk Fish. Deskripsi tool menjanjikan Bash pada Unix (`tools.ts:1554`). Log terbaru maupun log 15:37 menunjukkan heredoc Bash ditolak parser Fish.

Agent berhasil bekerja lagi setelah menulis script ke file pada run terbaru; ini menambah giliran, latensi, dan isi history, tetapi bukan penyebab langsung stop 21:28. Rencana: tetapkan executable Bash untuk tool Bash, atau dukung shell eksplisit dengan kontrak dan instruksi yang sesuai; jangan mengubah login shell pengguna.

## Rencana solusi berurutan

1. **Media normalization dan request admission (P1).** Buat normalizer bersama untuk composer upload, read-image, screenshot browser/computer, dan hasil MCP. Pertahankan file sumber, resize/encode salinan khusus model, simpan dimensi/scale agar koordinat Computer Use tetap benar. Hitung byte UTF-8 body JSON final, jumlah pesan, dan token/output reserve secara terpisah. Tetapkan budget berdasarkan endpoint gateway dengan margin dari 4,5 MB; jangan menerapkannya sembarang ke semua provider. Jika media terlalu besar, kompres dengan kualitas yang memadai atau laporkan kebutuhan crop/inspeksi terpisah secara eksplisit.
2. **Recovery 413 yang mengubah request (P1).** Maksimal retry terbatasi setelah ukuran benar-benar turun. Jangan menyamakan 413 dengan model tanpa vision atau menghapus gambar diam-diam. Bila input penting tidak bisa dipertahankan dalam budget, tampilkan alasan dan tindakan pemulihan. Untuk kebutuhan multi-image resolusi tinggi, evaluasi upload file/URL berotorisasi atau jalur gateway dengan batas body sesuai kebutuhan; perubahan penyimpanan/infrastruktur bukan syarat patch awal.
3. **Hasil run yang tegas (P2).** Bawa outcome `completed | failed | cancelled`, kategori error, dan ringkasan pemulihan pada event akhir. Notifikasi, suara, status chat, dan hasil IPC harus memakai outcome yang sama. Pada 413, gunakan pesan singkat yang menjelaskan ukuran request dan langkah pemulihannya, melalui kelima bahasa yang didukung.
4. **Konteks kelanjutan dan shell (P2).** Pertahankan persyaratan awal/terbaru, keputusan, file, dan pekerjaan tersisa dalam konteks terstruktur; summarization terukur saat perlu dan raw transcript tetap tersedia. Hindari pemotongan buta bagian tengah brief. Pisahkan kontrak Bash dari login shell pengguna. Perubahan shell dapat dikerjakan terpisah dari patch media.
5. **Telemetry dan acceptance.** Catat `runId`, kategori terminal, status HTTP, endpoint host, `requestBytes`, `imageBytes`, `imageCount`, `messageCount`, dan strategi recovery tanpa base64, auth header, atau isi pribadi. Uji dua PNG penyebab kejadian, satu gambar besar, kombinasi media + history panjang, endpoint berbeda, Unicode byte count, resume setelah error, tool pair tetap valid, dan pembatalan saat recovery. Verifikasi resize dengan teks kecil serta pemetaan koordinat screenshot. Integrasi Electron harus membuktikan failure tidak menghasilkan notifikasi sukses.

## Implementasi lanjutan

Kelima bagian rencana di atas telah dikerjakan pada working tree yang sama. Tidak ada commit, push, deployment, atau inference ke model berbayar dalam verifikasi ini.

1. **Normalisasi dan admission.** `electron/model-image.ts` menggunakan decoder/encoder Electron, tanpa dependency native tambahan. Salinan untuk model dibatasi ke sisi terpanjang 1.568 piksel dan target 500 KiB per gambar. PNG dipertahankan bila muat; JPEG dan resize bertahap dipakai saat perlu. Pengecilan berhenti sebelum detail harus dikorbankan secara berlebihan, lalu memberi error yang meminta crop/konversi. File asli tidak ditulis ulang. `request-payload.ts` memproyeksikan seluruh pesan sebelum fetch, sehingga upload, gambar hasil read, Computer Use, serta hasil MCP memakai jalur yang sama; screenshot browser yang dibaca sebagai file juga melewati jalur ini. Metadata dimensi/scale internal tidak dikirim sebagai field provider; catatan pemetaan x/y dihitung ulang untuk gambar model.
2. **Budget gateway dan recovery.** Host `router.const.web.id` memakai budget body JSON final 4.000.000 byte UTF-8, dengan ruang di bawah batas deployment 4,5 MB. Endpoint lain tidak otomatis mewarisi batas tersebut; SDK menyediakan override eksplisit. Media remote tetap berbentuk URL dan tidak diunduh. HTTP 413 mendapat maksimal satu recovery dengan target lebih kecil. Request kedua ditolak secara lokal bila ukurannya tidak turun; tidak ada retry identik atau downgrade vision/model. Gambar dan teks asli tetap ada dalam history.
3. **Outcome konsisten.** Event `run_end` membawa runId, outcome, kategori error, dan strategi recovery. IPC dan `agent:session-ended` meneruskan hasil yang sama. Habis batas giliran dan respons kosong tidak diklaim sukses. Main, companion, child agent, dan scheduled task mempertahankan hasil gagal. Notifikasi selesai dan chime hanya untuk completed; failed memakai notifikasi gagal, cancelled tetap tenang. Pesan payload, kegagalan persiapan gambar, dan notifikasi tersedia dalam lima bahasa serta mengikuti perubahan bahasa selama session. Internal transport abort tidak disamakan dengan pembatalan pengguna hanya karena teks error mengandung “abort”.
4. **Kelanjutan dan Bash.** Semua instruksi human dan keputusan/rencana assistant yang telah disampaikan tetap utuh. Packing jumlah pesan mengarsipkan pertukaran tool lama sebagai record terstruktur yang memuat nama, argumen, path, dan hasil; pasangan tool terbaru tetap valid. Tidak ada panggilan model ringkasan tambahan. Tool Bash pada Unix memilih executable Bash, bukan shell login Fish; shell terminal pengguna tidak diubah.
5. **Telemetry dan regresi.** Request memiliki endpointHost, requestBytes, imageBytes, imageCount, messageCount, runId, status HTTP, kategori kegagalan dan recovery. Metadata ini juga disimpan pada telemetry request. Diagnostik hanya memuat angka/identitas teknis, tanpa body, base64, signed URL, atau auth header. Penolakan admission lokal juga menghasilkan diagnostic event.

### Batas penggunaan

Budget byte tidak menggantikan batas token, jumlah pesan, atau ketentuan media provider. Input yang tidak dapat diperkecil secara memadai akan dihentikan dengan pesan pemulihan yang jelas; tidak ada jaminan semua jumlah/resolusi gambar dapat dikirim sekaligus. Encoding memakai Electron dan perlu divalidasi pada OS lain bila akan dirilis lintas platform; verifikasi native sesi ini berjalan di Linux. Berkas chat/file asli pengguna tidak dimigrasi atau diedit oleh normalizer. Untuk uji manual berikutnya, restart desktop app agar seluruh perubahan Electron termuat, lalu ulangi chat/gambar penyebab kejadian dan tes “lanjutkan”.
